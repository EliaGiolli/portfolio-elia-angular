From diagnosis to deployment

Before Angular, I was diagnosing network and software incidents on logistics systems under real time pressure. That habit carried over directly: isolate the problem, trace it to its root cause, fix it, document it — the same discipline I now bring to debugging a broken effect or a failed API call.

It also means I think past the component boundary — how a front end authenticates against a REST API, where state actually lives, what happens when the network fails. That, plus working fluency in five languages, makes cross-team communication — with users, with backend engineers, with whoever inherits the code next — second nature rather than an afterthought.
